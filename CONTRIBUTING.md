## Release versions

Before every release push, update `SocketJack/SocketJack.csproj`, `SocketJack.Windows/SocketJack.WPF.csproj`, and their README version references to `yyyy.MM.dd.revision`, using the release date in America/Chicago. Begin each date at revision `0`; increment the revision for another release on the same date. Each published version is immutable and must be unused on NuGet.

Run `pwsh -File tools/Verify-ReleaseVersion.ps1` and `pwsh -File tools/Verify-ReleaseVersion.ps1 -Project SocketJack.Windows/SocketJack.WPF.csproj -PackageId SocketJack.WPF` before packaging. The publishing workflow runs both checks and fails when a version has the wrong date or is already published. Confirm both packages are downloadable from NuGet after the workflow finishes; a successful build alone does not establish publication.

Both libraries use the same release version. After packing, run `pwsh -File tools/Get-ReleasePackages.ps1` to verify the two-package allowlist, package identities, repository links, and package contents. The workflow publishes these exact packages to NuGet and GitHub Packages, then creates the matching `v<version>` GitHub Release at the built commit with both `.nupkg` assets and `SHA256SUMS`. Confirm the release assets and both registry versions after publication.

The Unity family is versioned independently from SocketJack and SocketJack.WPF. Its six packages are `SocketJack.Unity`, `SocketJack.Unity.Web.Client`, `SocketJack.Unity.Web`, `SocketJack.Unity.Voice`, `SocketJack.Unity.Voice.Web.Client` and `SocketJack.Unity.Voice.Web`. Keep all six project versions on the same `yyyy.MM.dd.revision` date code and update their README references together. The base remains dependency-free; the Web and Voice packages are optional. A Unity-family release does not require republishing the core/WPF family.

`tools/UnityPackageFamily.psd1` is the explicit package, dependency, shipped-source and embedded-resource allowlist. Update it deliberately when the public package boundary changes. `tools/Get-UnityPackageFamily.ps1` checks the source graph; `tools/Verify-UnityRelease.ps1` requires today's America/Chicago date and an unused version for every ID. After packing, run `tools/Verify-UnityPackageFamily.ps1 -PackageRoot <owned-output> -WriteChecksums` and `tools/Test-UnityPackageVerification.ps1 -PackageRoot <owned-output> -OutputDirectory <fresh-owned-test-output>`. Verification checks all six identities, dependency versions, exact source bytes, managed assembly references, embedded resources, bounded archive contents and the absence of debug/private machine paths. NuGet repository signatures are the only archive entries excluded when comparing a feed download with its accepted build artifact.

`unity.yml` validates source pushes, pull requests and Unity release tags without publishing. Both Windows and Linux run multiplayer, Web persistence/API, voice and account-voice tests; Linux installs its OS `libsqlite3-0` prerequisite and runs the 2,000-peer UDP loopback smoke. Windows uses the inbox `winsqlite3.dll`. CI uses .NET 8 and 10; licensed Unity native/WebGL checks remain separate reproducible acceptance tooling. These checks do not establish production Internet capacity.

Publish through the established trusted `dotnet.yml` workflow by manually selecting `releaseTarget: unity` at the audited source ref. It validates the whole family, downloads and verifies the immutable build artifact, requests NuGet credentials immediately before publication, pushes packages in dependency order, verifies every downloadable payload, then creates `socketjack-unity-v<version>` with six package assets and `SHA256SUMS`. NuGet publishing is not atomic across six IDs: if a partial publication occurs, preserve the published immutable versions and investigate before retrying. Before the first optional-package release, configure the owner's trusted-publishing policy for `dotnet.yml` to cover all six IDs and permit new-package creation as well as new versions; a base-only policy is insufficient. See the [official NuGet trusted-publishing scope documentation](https://learn.microsoft.com/en-us/nuget/nuget-org/trusted-publishing). The existing `releaseTarget: core` default and master-push behavior continue publishing the core/WPF family.
