SocketJack.Unity.Voice.Web is the optional native account-server integration for voice. Client applications use SocketJack.Unity.Voice.Web.Client and do not need this server package or its database dependencies.

Construct `AccountVoiceRelay` with a `SocketJackWebServer` before starting the server. It registers the fixed authenticated `/ws/voice` role. Attach the role to the canonical hub and each enrolled leaf; a leaf proxies the binary role to its configured hub. The hub resolves canonical account, group/community membership, ignore/mute and trusted game-presence permissions. Global and community voice can cross linked servers sharing that account hub. Independent account stores are separate deployments.

In native Unity hosting, add `SocketJackWebVoiceHost` beside `SocketJackWebHost`. Add the Voice module for game-session UDP/TCP voice as well. The host adapter connects authenticated game-peer/account mappings to voice permission snapshots. Potential account-store I/O runs in two bounded background jobs, with 100 ms refresh and a 200 ms fail-closed snapshot expiry; the physics/session owner thread only reads RAM snapshots. Place this server adapter in the optional native host assembly, excluded from browser builds.

The web server authenticates the first bounded text frame before handing binary audio to this module. Expired sessions, logout, account bans and password recovery revoke the socket. Players cannot choose sender account IDs or supply an audience. Nearby voice requires a game-server presence; ordinary signed-in web clients can use their authorized account channels without forging a position. Audio never enters persistent social snapshots, chat history or logs.

Defaults allow 4,096 connected account voice sockets, 32 concurrently active senders, 4,096 recipients per frame, eight queued frames per socket and 262,144 forwarded frames per second. Configure `AccountVoiceRelayOptions` for the operator's CPU/bandwidth budget. Each account has one current voice socket; a replacement revokes the prior one. Per-speaker packet limits, replay windows, fixed packet bounds and a 500 ms audio age limit constrain abuse and stale playback. Queues discard oldest audio on congestion. These bounds do not replace network capacity planning.

Remote account hosting requires HTTPS/WSS and a valid certificate; loopback HTTP/WS is for development. Use the Web module's existing enrollment and account administration flows. This package does not provision a hosted relay or account service. Keep databases, live configuration and certificates outside public source and package assets.
