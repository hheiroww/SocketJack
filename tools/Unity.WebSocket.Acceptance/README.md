# Actual WebGL WebSocket acceptance

This isolated fixture builds a real Unity WebGL/IL2CPP player and runs it in a separate headless Chromium profile against the portable WebSocket game transport. It checks browser-native JavaScript callbacks, the actual manager/provider path, a 6,000-byte member baseline, owner input and a 6,100-byte member update. It never opens the user's browser profile or requests router mapping.

The build requires a licensed Unity Editor with its matching WebGL module, .NET 8, Node.js with the built-in WebSocket API, and an installed Chromium browser (including the matching Chromium headless shell). Run `Build-And-Test.ps1` with explicit `-UnityEditor`, `-Browser`, an owned `-OutputDirectory` outside source, and a fresh `-RunName`. Add `-UseRelay` to exercise the authenticated outbound host tunnel and browser relay connector instead of direct game connections. The relay fixture uses deliberately nonsecret loopback-only tickets; production tickets must come from the authenticated account API and must never be embedded in a player or URL.

`BrowserProbeBuild.Build` accepts `-browserOutput`; the fixture server accepts game port, allowed page origin, ready-file, stop-file, receipt-file and optional `relay` arguments. `probe-browser.mjs` accepts Chromium executable, WebGL build directory, fresh owned output directory, game port, HTTP port and optional `relay`. Keep all generated projects, browser profiles and receipts outside source control. The native fixture derives the same registered-prefab/member compatibility declaration as this test's Unity manager; changing either schema requires updating both sides.

Run the server only on loopback for this test. Stop it through its task-owned stop file; the browser runner closes only the browser process it created using the DevTools `Browser.close` command. No process killing or output deletion is performed. These sources are test tooling and must not be included in release packages.
