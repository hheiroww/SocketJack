# Actual browser account and Voice acceptance

This isolated fixture builds an actual Unity WebGL/IL2CPP client and starts a loopback .NET account/Voice server. It tests the shipped Unity account adapter's registration, logout, login and realtime text chat; the browser text-authentication/binary-Opus Voice socket; generated PCM encoding and decoding; the browser Web Audio DSP graph and clock; explicit microphone start, PTT gating and stop; and account logout teardown.

The runner creates its own headless Chromium profile with `--use-fake-device-for-media-stream` and `--use-fake-ui-for-media-stream`. Capture is generated by Chromium's synthetic device, never a user's physical microphone. The test player refuses capture without the isolated runner's loopback-only marker. The autoplay test flag permits deterministic audio-graph analysis; it does not verify physical speakers or a real browser permission gesture. Production capture is always opt-in and may require HTTPS, browser permission and a click/tap to enable audio.

Run `Build-And-Test.ps1` with an installed licensed Editor and matching WebGL module, a Chromium/headless-shell `-Browser`, a fresh owned output directory outside source and a fresh `-RunName`. Optional `-RuntimeDirectory` accepts the explicit validated module dependency bundle; otherwise it builds the public module graph. Only four client SDK assemblies, Concentus and the five approved Microsoft runtime dependencies enter the browser project. Server/database assemblies and build-only System.Numerics.Vectors are excluded. Include the UnityWebRequest module.

All generated projects, binaries, browser profiles, synthetic test accounts and receipts remain outside source control. The runner refuses unrelated projects and active owned processes. It closes only its browser via DevTools and stops its server through its owned stop file, with no process killing or output deletion. The reusable fixture source is test tooling and must not ship in NuGet or Asset Store product archives. Loopback WS/HTTP acceptance does not establish Internet WSS behavior or production capacity.

`node test-bridges.mjs` runs hardware-free JavaScript tests for opt-in capture, PTT gating, frame resampling, bounded output scheduling and teardown, text/binary WebSocket messages, backpressure and oversized-frame rejection. Both managed CI operating systems run these checks; actual IL2CPP/browser acceptance remains separate.
