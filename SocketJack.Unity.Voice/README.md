SocketJack.Unity.Voice is an optional voice module. The base multiplayer runtime does not depend on an audio codec or microphone APIs. This module uses the managed Concentus Opus codec; no native codec binaries or loader are included.

Add `SocketJackVoiceManager` to the same scene object as `NetworkManager`. Keep microphone capture off until the player explicitly chooses to start it; call `StartCapture()`/`StopCapture()`. Push-to-talk defaults to V with the legacy Input Manager. With the new Input System, disable keyboard polling and feed `SetPushToTalk(bool)` from an action. An optional `TransmitObject` selects the locally owned player; otherwise the first ready owned object is used. Call `SubmitPcm` for a game-provided mono capture adapter (320 float samples at 16 kHz per 20 ms frame); it does not open a microphone.

On the authoritative server, assign `MembershipProvider` before starting the session. `SocialVoiceMembershipProvider` maps authenticated game peers to account IDs, online presences and `SocialService` channel membership/ignore/mute permissions. Unknown identities are denied. `AllowTrustedGuests` is an explicit alternative for a trusted local/demo session and supports only proximity/global audiences. It does not authenticate accounts. Never enable it as a substitute for Internet authentication.

The speaker must own a current, visible network object. Object authority epochs and per-peer view tokens revoke in-flight voice after ownership/visibility changes. Proximity listeners also pass the game's visibility check and trusted position range. Party, raid, community and whisper audiences come from the membership provider. Global is an authorized broadcast audience, subject to configured fan-out limits. The module never accepts a sender account or recipient list from a player packet.

`NetworkVoiceServer` and `NetworkVoiceClient` also work without Unity. Pump the voice server's `Update(monotonicSeconds)` once before the associated session's `Update`. Reserve custom message IDs 60010/60011, unreliable delivery on channel 3. Each voice stream has its own sequence/replay history; the shared transport channel does not sequence different speakers against one another. TCP and WebSocket transports still inherit reliable stream head-of-line behavior.

Defaults are 20 ms mono Opus at 16 kHz/24 kbps, a 256-byte encoded-frame limit, 32 active playback speakers, a 10-frame jitter window with three initial buffering frames, a two-second stream timeout, 55 packets/second per speaker with a burst of ten, at most 64 recipients per frame and 512 forwarded frames per update. Configure `VoiceOptions` on portable services when the deployment requires different bounds. A larger global audience needs an explicitly sized relay/fan-out budget. Congestion drops voice rather than retaining a stale backlog. Opus decoding, capture encoding and jitter work run in one bounded background codec pump in the Unity adapter; Unity APIs remain on the main thread and the audio callback only resamples from a fixed PCM ring.

Portable codecs accept 8/12/16/24/48 kHz PCM. The 24 kHz adapter converts through the verified managed 48 kHz codec path while retaining standard 20 ms Opus packets. Microphone and speaker hardware, capture permissions and platform policies depend on the target platform. Native Unity capture uses `Microphone`; browser capture needs a browser-specific capture adapter. Gameplay UDP/TCP voice is plaintext unless the transport is separately secured. Use a secure transport or authenticated WSS audio bridge when confidentiality is required.

The fixture under `tools/Unity.Physics2D.Acceptance` is separate tooling. It is not included in this optional module or injected into customer scenes. Voice acceptance fixtures use synthetic PCM and do not record the developer's microphone.
